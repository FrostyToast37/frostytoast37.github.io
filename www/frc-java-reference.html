FRC Java Code Reference

A quick reference for understanding the structure of Team 587’s FRC Java code. The project uses WPILib’s command-based structure.

Project Structure

src/main/java/frc/robot/
├── Robot.java
├── RobotContainer.java
├── Constants.java
└── subsystems/
    ├── DriveSubsystem.java
    ├── MAXSwerveModule.java
    ├── CoralSubsystem.java
    └── Lights.java
File or folder Purpose
Robot.java Handles robot modes and the WPILib lifecycle.
RobotContainer.java Creates subsystems, commands, controllers, and button bindings.
Constants.java Stores configuration values and hardware IDs.
subsystems/ Contains classes that control robot mechanisms.

    ↓

Robot.java

Robot extends WPILib’s TimedRobot. WPILib automatically calls special lifecycle methods. 

public class Robot extends TimedRobot {
}

robotInit()

@Override
public void robotInit() {
  m_robotContainer = new RobotContainer();
}

Runs once when the robot program starts.

robotPeriodic()

@Override
public void robotPeriodic() {
  CommandScheduler.getInstance().run();
}

Runs repeatedly, approximately every 20 milliseconds.

The command scheduler:

  • Checks controller buttons
  • Runs active commands
  • Ends completed commands
  • Interrupts conflicting commands
  • Runs subsystem periodic() methods

autonomousInit()

@Override
public void autonomousInit() {
  m_autonomousCommand =
      m_robotContainer.getAutonomousCommand();

  if (m_autonomousCommand != null) {
    m_autonomousCommand.schedule();
  }
}

Runs when autonomous mode begins.

teleopInit()

@Override
public void teleopInit() {
  if (m_autonomousCommand != null) {
    m_autonomousCommand.cancel();
  }
}

Cancels autonomous when driver control begins.

RobotContainer.java

RobotContainer connects the robot’s parts together. It usually contains:

  • Subsystem objects
  • Controller objects
  • Default commands
  • Button bindings
  • Autonomous command setup

Creating a Subsystem

private final DriveSubsystem m_drive =
    new DriveSubsystem();
Part Meaning
private Only this class can directly access it.
final The variable cannot point to a different object later.
DriveSubsystem The object type.
m_drive The variable name.
new DriveSubsystem() Creates the object.

Creating a Controller

XboxController m_driverController =
    new XboxController(
        OIConstants.kDriverControllerPort);

The constructor receives the controller port number.

new XboxController(int port)

Constants.java

Constants store values used throughout the project.

public static final double kDriveDeadband = 0.05;
Keyword Meaning
public Other classes can access it.
static Belongs to the class, not one object.
final Cannot be changed.
double Decimal number type.
kDriveDeadband Constant name.

Constants are grouped by purpose:

DriveConstants.kMaxSpeedMetersPerSecond
OIConstants.kDriverControllerPort
CoralConstants.kWristL2Angle
AutoConstants.kPXController

Grouping constants prevents unexplained numbers from being scattered throughout the project.

Subsystems

A subsystem owns and controls one part of the robot. 

public class DriveSubsystem extends SubsystemBase {
}

Subsystems commonly:

  • Create motor and sensor objects
  • Control hardware
  • Track mechanism state
  • Provide methods for commands
  • Update sensors in periodic()

Subsystem Constructor

public DriveSubsystem() {
  resetEncoders();
}

A constructor runs once when the subsystem is created. Constructors are commonly used for creating hardware objects, configuring motors, resetting sensors, and setting up odometry.

periodic()

@Override
public void periodic() {
  // Repeated sensor and state updates
}

The command scheduler repeatedly calls this method. Team 587 uses subsystem periodic methods to update odometry and publish values to SmartDashboard.

Common Subsystem Methods

drive()

public void drive(
    double xSpeed,
    double ySpeed,
    double rot,
    boolean fieldRelative)
Parameter Type Purpose
xSpeed double Forward/backward speed.
ySpeed double Sideways speed.
rot double Rotation speed.
fieldRelative boolean Whether movement is field-relative. 
m_drive.drive(0.5, 0, 0, true);

Getter Method

public Pose2d getPose() {
  return m_odometry.getPoseMeters();
}

A getter returns information without directly exposing the internal field.

State-Setting Method

public void setState(coralState state) {
  // Set mechanism behavior
}

Example:

m_coralSubsystem.setState(coralState.LEVEL2);

Commands

A command describes an action that the scheduler can run. Command methods commonly return a Command.

Run Once

public Command zeroHeading() {
  return this.runOnce(
      () -> m_drive.zeroHeading());
}

runOnce() executes the action once.

Use it for:

  • Zeroing a gyro
  • Selecting a mechanism position
  • Resetting a sensor

Run Repeatedly

public Command setX() {
  return this.run(
      () -> m_drive.setX());
}

run() repeatedly executes the action while active.

Use it for:

  • Holding the drivetrain in an X configuration
  • Continuously controlling a mechanism
  • Repeatedly reading controller input

Lambdas

A lambda is a short function that can be passed to a command.

() -> m_drive.setX()

This means:

When the command runs, call m_drive.setX().

Compare the following:

m_drive.setX();

This runs immediately.

() -> m_drive.setX()

This describes an action to run later.

Default Commands

m_drive.setDefaultCommand(
    new RunCommand(
        () -> m_drive.drive(...),
        m_drive));

A default command runs whenever no other command is using that subsystem. 

No special command active → joystick driving
Special command active     → joystick driving is interrupted
Special command ends        → joystick driving resumes

The final m_drive argument declares that the command requires the drive subsystem.

Subsystem Requirements

new RunCommand(
    () -> m_drive.drive(...),
    m_drive);

The last argument tells WPILib which subsystem the command controls. Only one command that requires a subsystem can normally run at a time. 

Default drive command requires DriveSubsystem
Auto-align command requires DriveSubsystem

Starting auto-align interrupts the default drive command.

Button Bindings

onTrue()

new JoystickButton(
    m_driverController,
    XboxController.Button.kStart.value)
    .onTrue(zeroHeading());

Runs when the button is pressed. Use for one-time actions.

whileTrue()

new JoystickButton(
    m_driverController,
    XboxController.Button.kRightStick.value)
    .whileTrue(m_autoAlignRight);

Runs while the button is held. Use for continuous actions.

Button Constructor

new JoystickButton(controller, buttonNumber)
Parameter Purpose
controller Controller being checked.
buttonNumber Button being checked.

Method References

m_drive::getPose

A method reference passes an existing method to another object.

Equivalent lambda:

() -> m_drive.getPose()

Another example:

m_drive::setModuleStates

Equivalent lambda:

states -> m_drive.setModuleStates(states)

Swerve-Specific Objects

SwerveModuleState

new SwerveModuleState(
    speed,
    angle)

Represents the desired state of one swerve wheel.

new SwerveModuleState(
    0,
    Rotation2d.fromDegrees(45))

This means:

  • Wheel speed: 0
  • Wheel angle: 45 degrees

Pose2d

new Pose2d(
    xPosition,
    yPosition,
    rotation)

Represents the robot’s position and heading on the field.

Rotation2d

Rotation2d.fromDegrees(90)

Creates a rotation from degrees.

Translation2d

new Translation2d(x, y)

Represents a position or waypoint on the field.

Autonomous Commands

new SwerveControllerCommand(
    trajectory,
    m_drive::getPose,
    DriveConstants.kDriveKinematics,
    xController,
    yController,
    thetaController,
    m_drive::setModuleStates,
    m_drive);
Argument Purpose
trajectory Path for the robot to follow.
m_drive::getPose Supplies the current robot position.
kDriveKinematics Describes the swerve drivetrain.
xController Controls X movement.
yController Controls Y movement.
thetaController Controls rotation.
m_drive::setModuleStates Sends wheel commands.
m_drive Declares the drivetrain requirement.

andThen()

return command.andThen(
    () -> m_drive.drive(0, 0, 0, false));

Runs the second action after the first command finishes. Here, the robot is commanded to stop after the trajectory ends.

How to Read the Code

When following a behavior, use this path:

    ↓
Command method
    ↓
Subsystem method
    ↓
Motor or sensor object

For joystick driving:

    ↓
Deadband filtering
    ↓
DriveSubsystem.drive(...)
    ↓
Swerve kinematics
    ↓
Swerve module states
    ↓
Individual wheel modules

    ↓
getAutonomousCommand()
    ↓
Trajectory command
    ↓

    ↓

    ↓
DriveSubsystem
